Advanced Radial Menu System ​

1. Introduction ​

The Advanced Radial Menu System is a flexible and easy-to-use radial menu framework built for Unreal Engine. It gives players a quick and intuitive way to select actions using directional input, whether they’re using a mouse, keyboard, or controller.

The system is designed to be data-driven, meaning you can define menu items using Data Tables instead of hardcoding them. This makes it much easier to create, update, and manage menu options without touching the core logic. It also supports multi-level menus, so you can organize items into categories and sub-categories by linking data tables together.

Visually, the menu is powered by materials, giving you full control over how it looks. You can customize colors, backgrounds, borders, highlights, and even adjust the size of different zones like the cancel area or item ring to match your UI style.

Integration is straightforward—just attach the radial menu component to your pawn, set up your data tables, and you're good to go.

The system includes:

  • Material-based radial menu rendering
  • Data Table–driven menu items
  • Support for multi-level menus with sub-categories
  • Runtime visual customization (colors, highlights, etc.)
  • Adjustable radial zones (cancel area, item ring, search ring, etc.)
  • Mouse, keyboard, and controller support
  • Easy setup through an actor component

2. Installation ​

  1. Add the Asset Pack content to your project.
  2. Ensure the following built-in plugins are enabled in Edit → Plugins:
  • Common UI
  • Enhanced Input
  1. Restart the editor.
  2. Project Settings -> Engine -> Input -> Default Classes -> Set both options to Enhanced Input.

3. System Overview ​

The Advanced Radial Menu System is designed to be modular, data-driven, and easy to integrate into any Unreal Engine project. The system is built around a set of components that handle input processing, radial menu logic, and visual rendering through a material-based interface. By combining Actor Components, Data Tables, and Material-based rendering, the system allows developers to quickly create customizable radial menus without modifying core logic.

Actor Components ​

The system provides two actor components that can be attached to a Pawn or Character depending on the type of radial interaction required. These components manage the radial menu logic, input handling, and communication with the UI.

AC_RadialQuickAccess ​

The AC_RadialQuickAccess component is designed for fast and responsive selection during gameplay. It is intended for scenarios where the player needs to quickly select an option and immediately execute the associated action.

In this mode, the radial menu opens when the assigned input is triggered. The currently selected item is determined by the direction of the cursor or controller stick relative to the center of the menu. When the input is released, the highlighted item is selected and its associated action is executed. If the cursor remains within the cancel area, no action is triggered.

This component is commonly used for:

  • Weapon selection

  • Ability selection

  • Tool switching

  • Quick commands or emote menus

AC_RadialShopController ​

The AC_RadialShopController component is designed for shop-style or browsing interactions, where users may need more time to explore available options before making a selection.

Unlike quick access menus, this mode allows users to navigate through items without immediately executing an action. The menu remains open while the player browses the available options and confirms their choice through the appropriate input.

This component is typically used for:

  • Item shops

  • Inventory category selection

  • Equipment or upgrade menus

  • Store-style radial interfaces

Both components use the same underlying material-based radial menu system and data table structure, allowing developers to switch between interaction styles while maintaining consistent visuals and configuration.

B. Actor Component Configuration ​

After adding the desired radial menu actor component to a Pawn or Character, several parameters can be configured to control the behavior and data used by the radial menu. These settings allow developers to define the menu structure, input behavior, and visual configuration of the menu.

Data Table Configuration ​

The radial menu is data-driven, meaning that all items displayed in the menu are defined using a Data Table. The actor component contains a property where the user can assign the primary data table that will be used to populate the radial menu.

Each row in the data table represents a radial menu item and can include information such as:

  • Item name

  • Icon used in the radial menu

  • Associated action or identifier

  • Reference to another data table for creating sub-categories

By linking one data table to another, users can create multi-level radial menus, allowing categories to expand into additional radial menus.

Input Configuration ​

The actor component works with Unreal Engine's Enhanced Input System to detect when the radial menu should open, navigate, and confirm selections.

Users can configure input actions to:

  • Open the radial menu
  • Navigate the menu using mouse movement or controller analog stick
  • Confirm selection
  • Cancel or close the menu

Because the selection logic is angle-based, the system calculates the cursor or stick direction relative to the center of the menu to determine the active sector.

Visual Configuration ​

Since the radial menu is rendered using a material-based system, the actor component exposes parameters that allow developers to control the visual appearance of the menu.

Users can configure:

  • Sector color

  • Background color

  • Border color

  • Highlight color

  • Opacity values

In addition to colors, the radius of different zones within the radial menu can be adjusted to match the desired layout.

These include:

  • Cancel Area Radius – The inner region where no item is selected.

  • Item Ring Radius – The area where the radial items are displayed.

  • Chosen Indicator Ring Radius – The indicator for the previous selected items.

  • Search Ring Radius – The outer ring used for item detection and highlighting.

These parameters allow developers to easily adapt the radial menu to different UI styles without modifying the material itself.

Input Device Support ​

The radial menu components support both mouse & keyboard and controller input. The selection direction is calculated from either the mouse position or the controller’s analog stick, ensuring consistent behavior across input devices.

This allows the same radial menu configuration to work seamlessly across PC and gamepad-based interactions.

C. Example Use Cases ​

The Advanced Radial Menu System can be used in a wide variety of gameplay and UI scenarios where users need to quickly select between multiple options. Because the system is data-driven and supports multi-level menus, it can be adapted for both simple quick-access menus and more complex category-based interfaces.

To demonstrate the flexibility of the system, the included demo project contains two example implementations using the provided actor components.

Quick Select Radial Menu (Weapon Selection) ​

The Quick Select radial menu demonstrates a fast selection system typically used for switching weapons, abilities, or tools during gameplay. In this mode, the player opens the radial menu, selects a sector using directional input, and releases the input to immediately execute the selected action.

In the demo, the AC_RadialQuickAccess component is used to implement a weapon selection menu. Each sector represents a different weapon defined in the Data Table.

When a weapon is selected:

  • The chosen weapon is equipped on the pawn.
  • The pawn plays the correct holding animation based on the enum value assigned to the weapon in the actor blueprint.
  • The radial menu closes automatically after the selection is confirmed.

This setup demonstrates how the radial menu can be used for fast gameplay interactions such as:

  • Weapon switching

  • Ability selection

  • Tool selection

  • Quick commands

Store Style Radial Menu (Item Spawning) ​

The Store-style radial menu demonstrates a browsing interface where players can navigate through categories and spawn items from the radial menu.

In the demo, the AC_RadialShopController component is used to create a shop-like radial menu. Items are defined in the Data Table and can optionally link to other tables to create multi-level radial categories.

When the player selects an item:

  • The selected item is spawned into the world.

  • The item appears near the player, allowing them to interact with it immediately.

This setup demonstrates how the radial menu can be used for systems such as:

  • Item stores

  • Inventory browsing

  • Equipment selection

  • Item spawning tools

These two examples illustrate how the same core radial menu system can be adapted for different gameplay scenarios simply by attaching the appropriate actor component and configuring the associated Data Tables.

D. Creating a Custom Radial Actor Component ​

The system is designed to be extensible, allowing you to create your own specialized actor components if the provided AC_RadialQuickAccess or AC_RadialShopController do not meet your specific needs. Since the core rendering is material-driven, your custom component can focus entirely on unique gameplay logic.

To create a custom component using the system's material, follow these steps:

  • Create a New Actor Component: In the Unreal Editor, create a new Blueprint class inheriting from Actor Component or duplicate one of the existing controllers to use as a template.
  • Reference the Radial Material: Ensure your component has a reference to the widget blueprint which uses MI_WheelMenu material instance. This material handles all the sector rendering, highlighting, and zone calculations.
  • Implement Selection Logic:
    1. Use the Angle-Based Calculation to determine which sector the user is pointing at. You can calculate the direction of the cursor or controller stick relative to the center of the menu to find the active sector.

    1. Define your own "Cancel Area" logic by checking if the input distance is within the defined Cancel Sector Radius.
  • Link to Data Tables: Structure your Widget Blueprint to read from a Data Table or Data Asset. This ensures your custom menu remains data-driven, allowing you to easily define item names, icons, and actions without changing the component's code.

Note: Currently both the Quick Selection and Shop Style uses datatable only but you can modify the Blueprint to use Data Assets or any other source.

  • Update Material Parameters: Use the Set Scalar Parameter Value or Set Vector Parameter Value nodes to update the material at runtime. You should pass the information to the following parameters in the material to update the visual highlights and colors. Note: When the cursor is within the "Cancel Radius," set the Active Angle to -1 to hide the highlight effect.

  • Handle Input Events: Integrate with the Enhanced Input System to trigger the opening and closing of your custom radial menu. You can define custom "Confirm" or "Back" behaviors while the menu is active.

By following this approach, your custom component will benefit from the high-performance, material-based rendering of the core system while providing the exact gameplay interactions your project requires.

E. Creating a Custom Widget Blueprint ​

The Widget Blueprint is responsible for both the visual presentation and interaction logic of the radial menu in the current version of the plugin.

At this stage, the C++ implementation provides only:

  • A reference to the main Data Table
  • A delegate for sector change events

All core interaction logic (selection, highlighting, input handling, etc.) is implemented in the provided Widget Blueprint. If you create your own custom widget, you will need to recreate or extend this logic manually.

1. Create a New Widget Blueprint ​

  • In the Content Browser: Right Click → User Interface → Widget Blueprint
  • Name it: WBP_RadialWheel (recommended)

2. Recreate or Reuse Core Logic ​

If you are not using the provided default widget, you must implement the following logic inside your Widget Blueprint:

  • Angle-based sector calculation
  • Mouse / controller direction handling
  • Active sector detection
  • Cancel zone (deadzone) logic
  • Selection confirmation behavior

You can:

  • Duplicate the provided WBP and modify it (recommended), or
  • Build your own from scratch

3. Setup Root Layout ​

Create a UI structure using:

  • Canvas Panel (root)
  • Image (Radial Background using MI_WheelMenu)
  • Overlay / Panels for icons and text

4. Assign Radial Material ​

  • Use the material instance: MI_WheelMenu
  • Apply it to an Image widget: Brush → Image → Material

This material handles:

  • Sector rendering
  • Highlight effects
  • Angle-based visuals
  • Cancel zone masking

5. Bind Data (Data Table) ​

Use the Data Table provided through the C++ class.

In Blueprint:

  • On Construct:
    • Get Data Table rows
    • Loop through entries
    • Populate UI elements (icons, names, etc.)

This ensures your radial menu remains data-driven.

6. Handle Sector Changes ​

Bind to the sector change delegate exposed by C++.

When triggered:

  • Update highlighted segment
  • Update text or preview panel
  • Trigger animations or sounds

7. Update Material Parameters ​

Use Blueprint nodes:

  • Set Scalar Parameter Value
  • Set Vector Parameter Value

Important parameters:

  • ActiveAngle
  • NumSegments
  • HoverIndex
  • CancelRadius

Special behavior: If the cursor is inside the cancel radius, set ActiveAngle to -1 to hide highlight effects.

8. Handle Input and Interaction ​

Since input is handled in Blueprint:

You must implement:

  • Mouse position tracking
  • Controller stick direction (optional)
  • Input events (open, close, confirm, cancel)

Use Enhanced Input or standard input events as needed.

9. Add Feedback and Polish ​

Recommended improvements:

  • Smooth highlight transitions
  • Scale or glow effects
  • Sound feedback
  • Tooltip or preview panel

10. Open / Close Behavior ​

Implement functions or events to:

  • Open the radial menu
  • Close the radial menu
  • Reset selection state

Important Note ​

In the current version of the plugin:

  • The system is Blueprint-driven
  • C++ acts as a lightweight foundation
  • Users are expected to define behavior inside Widget Blueprints

Future updates may move more logic into C++ for improved modularity and ease of use.

Best Practices ​

  • Duplicate the default Widget Blueprint as a starting point
  • Avoid rebuilding logic from scratch unless necessary
  • Keep UI and logic organized within the Blueprint
  • Use Data Tables for flexibility
  • Keep material parameter updates consistent

Result ​

With this approach, you can:

  • Customize UI freely
  • Extend functionality as needed
  • Maintain a data-driven workflow
  • Build your own radial menu behavior on top of the provided system
