Inventory, Crafting & Cooking System ​

Documentation ​

1. Introduction ​

The Inventory, Crafting & Cooking System is a modular and production-ready Unreal Engine plugin designed to integrate seamlessly into gameplay systems. It provides a flexible, data-driven inventory framework with advanced item management, equipment handling, and a fully integrated crafting workflow.

The system is built with extensibility in mind, allowing developers to configure items, recipes, and behaviors without modifying core logic. Most interactions are exposed to Blueprints for easy customization.

2. How To Install ​

  1. Add the Inventory Plugin to your project.
  2. Ensure the following built-in plugins are enabled in Edit → Plugins:
  • GamereadyInventorySystem
  1. Restart the editor.
  2. Add Gameplay Tag to the project as required. In order for the current inventory system to world user needs to add the below gameplay tags in the project settings.
  3. Add the inventory component to the player character class.

  1. Also needs to provide the following classes in the inventory component.
  • Crafting Recipe - Setting the Data-Table for the list of recipes.
  • Base Widget - Set the Inventory widget here.
  • Custom Drop - Drop widget that will pop-up.
  • Custom Transfer - Transfer widget that will pop-up.
  • Details Widget - Details panel widget that pop-up on hover.
  • Custom Pickup - Pickup widget that will pop-up.
  • Notification Widget - The notification widget.

3. System Overview

3.1 Dynamic Inventory Grid ​

The inventory layout is fully configurable. Developers can define the number of rows and columns, and the system automatically generates the slots at runtime.

  • Works with both standard grid and tab-based layouts
  • Designed for scalability across different gameplay scenarios

Item System ​

Data-Driven Item Setup ​

Items are created using Data Assets, allowing new content to be added without changing core code.

Each item can:

  • Spawn directly inside the inventory
  • Spawn in the world using an assigned Actor class
  • Be categorized using Gameplay Tags for filtering and slot validation

This structure keeps the system organized and easy to extend.

Drag & Drop Interaction ​

The drag-and-drop system is designed to feel intuitive and responsive.

  • Drag items between slots
  • Automatically swap items when necessary
  • Merge stacks if both items match and the stack limit is not reached
  • Drop items directly into the world
  • Drop items onto other items for contextual behavior
  • Double-click to transfer a full stack
  • Hold Shift while dragging to split half of a stack

All behaviors are handled internally to reduce manual setup.

Stack & Quantity Management ​

The system provides flexible control over item quantities.

  • Pick up custom quantities from the world
  • Drop custom quantities into the world
  • Split stacks using:
    • Single quantity
    • Half stack
    • Custom amount
  • Dedicated split interface for precise control
  • Split and drop functionality supported inside the search results container

This makes inventory management efficient even with large item counts.

World Interaction ​

Inventory and world interaction are tightly integrated.

  • Pick up items directly from the world
  • Automatically stack matching items when possible
  • Place remaining quantities into available slots
  • Equip items directly from the world

The transition between world objects and inventory items is seamless.

Equipment System ​

The equipment system supports dedicated equipp-able slots.

  • Only non-stackable items can be equipped
  • Equipped items can be replaced with other valid items
  • Equip items directly from inventory or world
  • Supports validation rules for equipment types

This ensures consistent behavior across gameplay systems.

Special Slot Support ​

Special slots can be configured to accept only specific types of items.

  • Validation based on Gameplay Tags or custom logic
  • Delegate triggered when a valid item is inserted
  • Ideal for crafting inputs, equipment slots, or restricted containers

Multi Inventory Interaction ​

The system supports inventory interactions between different Inventories.

  • Access other inventories
  • Transfer specific quantities
  • Double-click to transfer full stacks
  • Transfer all similar items with one action
  • Bi-directional “Transfer All” support

Designed to support trading systems, storage systems, and cooperative gameplay.

Search & Filtering ​

Managing large inventories is simplified with built-in search and filtering tools.

  • Real-time search bar
  • Compatible with tab-based layouts
  • Gameplay Tag-based categorization
  • Drag, drop, and split supported within search results

Bulk Actions ​

To reduce repetitive actions, the system includes bulk operations:

  • Transfer all items to another inventory
  • Transfer all similar items
  • Drop all similar items from inventory

UI & Feedback ​

The user interface is designed for clarity and responsiveness.

  • Item tooltips displayed on hover
  • Pickup and drop notifications
  • Modern UI for splitting and transferring
  • Clear display of item quantities and stack limits

Blueprint Extensibility ​

Core functionality is exposed to Blueprints, allowing developers to extend or customize behavior.

Available Blueprint access includes:

  • Adding items
  • Removing items
  • Transferring items
  • Equipping items
  • Retrieving all items and available slots

Delegates are also exposed for event-driven logic, including special slot interactions and crafting events.

3.2 Crafting System ​

Crafting Interface ​

The crafting system is integrated into the General Inventory and presented in a dedicated section. It is separate from the tab-based layout to maintain clarity and focus.

Recipe Configuration ​

Recipes are defined using a Data Table, allowing full control over:

  • Result item
  • Required materials
  • Required quantities

Developers can modify or expand crafting content without altering system logic.

Crafting Workflow ​

The crafting interface dynamically generates a list of all available recipes.

When a recipe is selected:

  • Required materials are displayed
  • Available quantities are shown
  • Missing materials are clearly indicated

This gives the player full visibility before crafting.

Craft Quantity Control ​

Players can control how many items they want to craft.

  • Increase and decrease buttons
  • Quantity automatically clamped to maximum possible
  • “Max” button for instant maximum selection

The system calculates craftable amounts in real time based on inventory contents.

Craft Validation & Execution ​

The Craft button is enabled only when requirements are satisfied.

When crafting:

  • Required materials are consumed.
  • Items reaching zero quantity are removed.
  • Crafted items are added directly to the inventory (not the hotbar).
  • Crafted items inherit full inventory functionality.

Crafted items behave exactly like standard items and can be stacked, transferred, equipped, or dropped.

Blueprint Events ​

The crafting system exposes events for further customization:

  • On Craft Started
  • On Craft Completed
  • On Craft Failed

These events allow developers to add:

  • Experience rewards
  • Sound and visual effects
  • Animations
  • Quest progression
  • Additional gameplay logic

3.3 Cooking System ​

Another component which provides a station-wise cooking system. It has both the feature of cooking with fire wood and without.

The main difference between cooking and crafting is that; cooking as a time variable factor and station factor.

Recipe Configuration ​

Recipes are defined using a Data Table, allowing full control over:

  • Result item
  • Required materials
  • Required quantities
  • Time factor

Developers can modify or expand cooking content without altering system logic.

Cooking Workflow ​

The cooking interface dynamically generates a list of all available recipes, the same as the crafting system.

When a recipe is selected:

  • Required materials are displayed
  • Available quantities are shown
  • Missing materials are clearly indicated

This gives the player full visibility before cooking. Also showing the progress in a progress bar.

Cooking Quantity Control ​

Players can control how many items they want to craft.

  • Increase and decrease buttons
  • Quantity automatically clamped to maximum possible
  • “Max” button for instant maximum selection

The system calculates cooking amounts in real time based on inventory contents. After cooking is done then the item is spawned on the platform where the player can collect them.

Cooking Validation & Execution ​

The Cook button is enabled only when requirements are satisfied. Once cooking starts the discard button gets activated; players can cancel the cooking process in between.

When cooking:

  • Required materials are consumed.
  • Required items are removed from the inventory.
  • Cooked items are spawned on their respective platforms, from where the item can be picked up from.
  • Cooked items inherit full inventory functionality.
  • On Cancel the items removed from the inventory are returned back to the inventory and if there are no slots available then the items are dropped on the world.

Cooked items behave exactly like standard items and can be stacked, transferred, equipped, or dropped.

4. Customizations And Design ​

In the plugin we provide all the UI and design customization for the user. Users can change the design of the slots and other layout from the widget itself without messing with the logical part; a huge advantage for designers who want to use an inventory system with their own layout.

  • The layout for the hand items and the equipable slot can be changed by the user.

  • We can even edit the individual slots; including their looks and their behaviour on how it will react when the slot is selected and deselected.
  • We can use the same slot for all the inventory slots in the plugin including the equipable and the hand item section as all. Also if the user wants they can just duplicate the slot widget and use different slots for each section; this creates a level of customization for the entire layout.

  • We can edit the items that can be cooked or crafted from the data tables that are provided and also we can set the icon and actors details from the data assets of each item.

  • Each of the pop-up menus is fully customizable and editable and also can be directly managed from the blueprint itself. Like for color change or for adding some audio files for clicks.

  • We can also edit the number of slots based on the requirement (max feasible <=15 ); this number can also be set directly from the widget itself.

The plugin is built to give users full control over both the look and functionality of their inventory system. From customizing slot layouts and visual styles to defining item behavior and crafting data, everything can be managed directly through Blueprints, data tables, and data assets. This ensures flexibility, easy iteration, and a smooth workflow for developers to design and adapt the system to their game’s needs without heavy code changes.
